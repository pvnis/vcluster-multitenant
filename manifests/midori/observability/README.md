# midori observability: one stack, an admin view and a view per tenant

Built 2026-10-08. Everything stateful runs on **midori-eye-0** (10.30.30.204;
4 vCPU / 7 GiB / 60 GB; label and taint `midori.role=observability`), a k3s
agent of the same cluster, so monitoring neither competes with tenants on the
GPU nodes nor dies with one of them. Tenants never see the node:
`nv-tenant.yaml` exposes only `gpu.vendor=nvidia` nodes.

    Grafana       http://<any node>:30300
                  admin: user admin, password in ~/midori-build/grafana-admin (cp-0)
                  tenants: user <tenant>, password in ~/midori-build/grafana-users/<tenant>
    Prometheus    7 d / 18 GB cap, 25 Gi PVC on eye     (cluster-internal only)
    Loki          7 d, 15 Gi PVC on eye, multi-tenant    (cluster-internal only)
    Alertmanager  no receivers yet: alerts show in Grafana and Alertmanager only

## How tenant isolation works

Every pod a tenant creates lands in exactly one host namespace, `tenant-…`,
and the syncer stamps it `vcluster.loft.sh/managed-by=<tenant>`, which a
tenant cannot forge. Both are used as the tenant key.

| layer | admin org ("midori admin") | tenant org (one per tenant) |
| --- | --- | --- |
| metrics | Prometheus directly | `prom-proxy-<tenant>` (prom-label-proxy), which rewrites every query to `namespace="<tenant>"`, its own selectors included |
| logs | Loki with `X-Scope-OrgID: platform\|tenant-…` | Loki with `X-Scope-OrgID: <tenant>` only |
| what it contains | everything | the tenant's pods by **their own names** (`vpod`, `vnamespace`), its quota, GPU slices, Cilium drops, its logs; vLLM for serving tenants |
| user role | Grafana admin | **Editor** in its own org, member of nothing else |

Not shown to tenants, on purpose: node metrics, physical GPU utilisation
(dcgm-exporter) and the slicing broker. A card's utilisation includes every
tenant on it, so it would tell a tenant how busy its neighbours are. Tenants
get their own slice (`tenant:gpu_slice_mib`, `tenant:gpu_weight`) instead.
Cilium drops are re-keyed onto `namespace` by `rules.yaml` with the far end
removed, so a tenant sees that it was probed but not by whom.

Tenant users are Editors and never org Admins: an org Admin can edit
datasources, and so could aim its Prometheus at the real one or change its
Loki tenant header.

**Tenants are now managed by the tenant controller (`../../../controller/`)**:
it creates each tenant's proxy, Grafana org, user, datasources and dashboards,
and keeps the admin org's Loki tenant list in Secret
`grafana-datasource-loki-admin` (Grafana's datasource sidecar), so the
per-tenant steps below (8, 9) are what it does, not what an operator runs.
`grafana-tenants.py` remains as the record; do not run it against
Tenant-managed tenants.

## Bring-up, in order

From `manifests/midori/observability/`, host kubeconfig:

1. Join eye as an agent (as any midori node: `../registries.yaml`,
   `../containerd-00-cni.toml`, kubelet `resolv-conf`), with
   `node-label` and `node-taint` `midori.role=observability`.
2. k3s servers: `etcd-expose-metrics: true`, rolling restart one at a time.
3. `kps-values.yaml` (kube-prometheus-stack 92.1.0), `scrape.yaml`,
   `rules.yaml`; per tenant `tenant-scrape-allow.yaml`.
4. Cilium: the metrics and dashboard keys now in `../cilium-values.yaml`, then
   `kubectl rollout restart ds/cilium deploy/cilium-operator` and check
   `Socket LB Coverage: Hostns-only` again.
5. GPU nodes: `gpusched-textfile.{sh,service,timer}` into
   `/usr/local/sbin` and `/etc/systemd/system`, timer enabled.
6. `dcgm-values.yaml` (dcgm-exporter 4.8.4).
7. `loki-values.yaml` (loki 7.3.0), `alloy-values.yaml` (alloy 1.13.0).
8. Per tenant `tenant-prom-proxy.yaml`.
9. Secret `grafana-admin`, `grafana-values.yaml` (grafana 10.5.15), the admin
   dashboard ConfigMap (`dashboards/admin-midori.json`, label
   `grafana_dashboard`), then
   `python3 grafana-tenants.py http://10.30.30.204:30300 ~/midori-build/grafana-admin ~/midori-build/grafana-users <tenants…>`.
   Idempotent; run it again for a new tenant, and add the tenant to the admin
   Loki header in `grafana-values.yaml`.
10. `../platform-guard.yaml` (see below). **Not optional.**

Dashboards are generated by `dashboards/build.py`.

## The platform guard, and the hole it closes

`../platform-guard.yaml` came out of testing this stack, and it is about more
than observability. The Cilium floor denies tenant → other tenant and tenant →
outside, and tenants may sync their own NetworkPolicies because those denies
beat anything they write. But nothing denied tenant → **platform**. From
tenant-nv-a, one NetworkPolicy with `egress: [{}]` reached Loki as any tenant
(read and **injected** log lines), Prometheus past the proxy, the HAMi
scheduler, the quota webhook, and the in-cluster registry, where it **started
an image push (202)**: it could have overwritten the quota webhook's own
image. The guard denies ingress from tenant namespaces to every endpoint in a
non-tenant namespace, except cluster DNS and the S3 gateway.

**Read its `enableDefaultDeny: false` before touching it.** The first version
lacked it, and a policy that selects an endpoint puts it into default-deny
even when it only denies. For **about 14 minutes (02:42–02:56)** the API
server could not reach the quota webhook, so no tenant pod could be created
anywhere (failurePolicy Fail); Grafana's NodePort went dark; the
metrics API was down (`KubeAggregatedAPIDown`). With the flag the policy is
purely subtractive, the attacks above stay blocked, and the regression pass
(targets, webhook, HAMi scheduling, S3, logs, Phoenix inference, tenant APIs)
is clean.

## Things that will look wrong and are not

- **gVisor pods have no per-container metrics.** cAdvisor sees the sandbox as
  one pod-level cgroup (`container=""`). kube-prometheus's stock dashboards
  filter `container!=""` and so show gVisor pods as empty; the midori
  dashboards use the pod-level series.
- **No `node_systemd_*` metrics.** containerd's default AppArmor profile denies
  node-exporter's D-Bus connection. The GPU nodes' unit states come from the
  `gpusched-textfile` timer instead (`midori_systemd_unit_active`).
- **`LLMInferenceService` READY=False** in tenant-phoenix is expected (see
  `../phoenix/README.md`); watch vLLM's metrics instead.

## Traps found while building it

- **vCluster writes a ServiceAccount token into a pod annotation**
  (`vcluster.loft.sh/token-…`). kube-state-metrics allowlists exactly
  `vcluster.loft.sh/object-name`, never `*`.
- **prom-label-proxy v0.15 has no `-value`** (the proxy exits printing usage),
  and with no `-label-value` it takes the tenant **from a query parameter the
  client controls**. `-label-value` is the security boundary.
- **Grafana 12 ignores `OrgId` when creating a user with `auto_assign_org=false`**:
  the user gets a personal org as its Admin and is not in the requested org.
  `grafana-tenants.py` adds the membership, switches the user, deletes the
  personal org (removing its last Admin is refused) and asserts the result.
- **The chart's `init-chown-data`** has only CAP_CHOWN: it works on an empty
  volume, then fails on every later start on Grafana's 0700 directories.
  Disabled.
- **dcgm-exporter's chart pins `scrapeTimeout: 25s`**; at a 15 s interval the
  operator drops the ServiceMonitor, and only its log says why.
- **Alloy's `loki.source.journal` with no `path`** opens the journal of the
  *container's* machine id and reads nothing while reporting healthy.
